### Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from build to merge, and nothing merges without your clean swarm verdict.** For "autopilot this queue", "full autopilot", and one-owner-per-PR programs. The job is a queue of independent PRs handed over to drive to merged with full autonomy. Orchestrate runs a standing program whose coordinator lands verified work itself and whose workers never merge; here each PR's owner carries the whole lifecycle through the merge, and the root keeps only verification, countersigns, and audits.

1. **Mark the operator's items and honor state-then-wait.** Items the operator names stay hers. She reviews and she clicks, and no owner merges one. When she asks for the protocol or the plan to be stated, deliver the statement and stop. Execution starts only on her explicit go. That go authorizes creating a goal with the full program objective and a thread heartbeat until the queue is done.
2. **Spawn one owner per PR with the full lifecycle.** One isolated Codex worktree agent per PR owns build, registration, self-proof, skeptical Bugbot triage, `$deslop`, `$no-comments`, a first rebase onto current trunk, and babysit to green. The first rebase happens before the code-ready report and babysit, even when trunk has not moved. During fix rounds, keep that merge base; rebase again only at merge prep, on a `git merge-tree` conflict with trunk, or when CI fails because trunk changed. Every owner keeps `decisions.tsv` and `children.tsv` trails; the latter records each subagent ID, expected runtime, and state. When shipped code is final, the owner reports its code-ready head SHA and each later push SHA that changes the patch. Self-proof, CI, and babysit run in parallel with the verifier swarm. Merge remains gated by step 4 and the user's explicit authority.
3. **Run owners in true parallel and never stack.** Many owners at once when PRs are self-contained: one writer per branch, disjoint files, cross-PR drift absorbed by rebase. Only genuinely overlapping work serializes. Self-contained PRs branch straight off main, and sequenced work is merge-then-branch. GitHub CLI (`gh`) is the default for PR operations. If `origin` is installed and resolves this repository, it may be used instead; record the selected forge. Never require Graphite (`gt`).
4. **Swarm-verify every round before its merge.** A round starts at the owner's code-ready head SHA and at each later push that changes the patch. At that SHA, fan out parallel independent verifiers per the **swarm** skill and aggregate to one verdict. The merge needs a clean verdict from the round whose patch matches the merge-ready head. Audit the receipts in the merge-ready report before the verdict. Re-run the gates at that SHA, prove the load-bearing behavior live on the real surface through a matching control skill, and audit the diff, distrusting the PR body. Use two or more focused audit lanes. The live lane is the floor, and a verdict without it is not clean. No merge without the root's clean verdict. Send every proven finding back to the owner in one fix-forward; defects filed as notes still count as findings. A behavior finding needs a red test for each affected site, or a reproduction receipt when a test cannot show it. A new patch gets a fresh swarm and verdict.
5. **On a clean verdict the owner merges and takes the next item.** The owner merges only from a head freshly rebased on trunk. If trunk moves before merge, use the patch-id rule in `playbooks/shipping.md` to decide which results remain valid; re-run mergeability and CI at the current head. The owner squash-merges its own PR through the selected forge and picks up its next self-contained item. The operator's full-autonomy grant plus the root's clean verdict authorizes the merge. Operator-named items stop at merge-ready and wait for the operator's click.
6. **Run the root layer.** A genuinely new raise of a pinned gate or budget value needs a fresh countersign after verifier proof. Use the authorized thread heartbeat for audit ticks around every 30 minutes. Never hold a shell open to sleep. At each tick, re-read this playbook from trunk and inspect the live goal. Audit the operation against both. Probe each owner through supported live status, collect decision trails, and count only side effects as progress. A lane that exceeds its expected runtime without a side effect is stuck. Cancel or stand it down, reconcile partial state, and dispatch at most one bounded replacement. Send a status message only when the audit found a tracked change no earlier message reported, such as a PR opened, code-ready head, verifier round, verdict, merge, blocker, or operator decision. Name each new change and nothing else; if nothing changed, end without a message. When merges batch, run a retro pass and a post-merge bot-comment sweep.
7. **Stand down instantly on the operator's stop.** Her hold or stand-down reaches every owner as a zero-writes order immediately. Owners hold their briefs until she releases them.

**Reply:** the queue with each PR's owner, state, and head SHA; each verdict and the swarm that produced it; what merged and what each owner took next; countersigns granted and why; open operator gates; where the collected decision trails live.
